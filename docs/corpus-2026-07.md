# Validation corpus — 2026-07-27

Nine open-hardware KiCad boards screened with `faraday_cli` at commit `bb01e4e`+.
The corpus exists to find **importer and rule bugs on real layouts**; the finding
counts below are screening-tier output, not a judgement on these designs.

Boards are fetched on demand (`scripts/fetch_corpus.py`), not vendored — only the
two fixtures under `cpp/tests/fixtures/real/` are committed, with attribution.

## Cross-format consistency (2026-07-29)

Every corpus board was also exported to ODB++ AND Gerber X2 by kicad-cli 9.0.7
and re-imported (`scripts/crossformat_corpus.py`) — all sides on the SAME
generic stackup, so the comparison measures the importers and nothing else.
**9/9 agree on both formats**: via counts exactly equal on every board through
BOTH ODB++ and Gerber; per-net routed copper exact on five boards (to the mm
through Gerber on all nine) and 0.3–9 % longer through the exports on the
arc-heavy ones (the exporter tessellates arcs finer than the importer's single
chord — more accurate, not less); findings within one everywhere except fomu.

Gerber importer bugs the sweep caught and fixed: KiCad emits `%TO.P,REF,PIN`
on pad flashes, not `%TO.C` — without parsing it, every real export's pads
were component-less and all THT pins became "vias" (bms-c1 805→1159); NPTH
mounting holes (merged into the same `.drl` by KiCad) counted as vias; and
via-in-pad needed the rule "a compless flash on ANY layer is a via ring",
calibrated until all nine boards matched the native import exactly.

Understood, exporter-side variances found and documented while getting there:
kicad-cli rewrites net names (spaces→`_`, `~X`→`~{X}`); its "best-effort" zone
conversion drops clearance holes, so pour coverage reads a few points higher and
fomu's borderline In1 (43.6 %→59.8 %) flips to plane — the extra copper is in
the exported job itself; netless micro-pads and consolidated FET pad grids
(bms-c1's 96-pad power packages) differ in pad count with no rule impact.
Importer bugs the sweep caught and fixed: NPTH mounting holes imported as vias,
custom-shape pads (surfaces in TOP subnets, fomu's FPGA) imported as pours, TH
pads duplicated once per copper layer, and a latent FID-index shift on
multi-island surfaces.

## Converter results

The switch-node and commutation-loop rules only fire on power topologies, which
is the point — they are silent on all five non-converter boards:

| board | switch nodes found | commutation loops |
|---|---|---|
| `vesc` (3-phase BLDC inverter) | `H1_VS`, `H2_VS`, `H3_VS` | 191, 166, 117 mm² |
| `mppt-2420-hc` (buck) | `/DC/DC/SW_NODE`, `/Power supply/SUPPLY_INPUT` | 267, 66 mm² |
| `mppt-2420-lc` (buck) | `/DCDC power stage/SW_NODE`, `/DCDC_OUT` | 71 mm² around SW_NODE (C4 at 4.4 mm) |
| hackrf-one, orangecrab, glasgow, fomu, ulx3s, bms-c1 | none | none |

VESC is the interesting case: its three phase nodes are found with **no inductor
present** (the motor is the inductance), while its *gate* nets — which also
gather 5–6 FET pads each — are correctly rejected because they never touch a
capacitor, inductor or connector. Trace width does **not** separate them (gate
nets there run up to 2.29 mm), so the test is topological, not dimensional.

## Bugs the corpus found (all fixed, all now regression-tested)

**1. False negative — a poured layer's own routing was skipped.** `bms-c1` has
58–89 % pour on *all four* layers, so every layer classified as a plane and every
segment was excluded: Faraday reported **0 findings on a 1097-segment board**. A
layer can be a reference *and* carry routing; the two concepts are now separate.
After the fix: 101 findings. This was the worst class of bug in the tool — a
confident clean verdict on an unanalysed board. `meta.planes[].routedMm` now
reports analysed length per layer so a "0 findings" verdict is auditable.

**2. Parse failure — vias inheriting drill from the netclass.** `vesc` has 7 vias
with no `(drill ...)`; the importer required it and refused the whole board. Drill
feeds no rule, so it is now optional, `0` means unspecified (never invented), and
`board.viasWithoutDrill` states the count.

**3. Unanalysable 6-layer boards.** Only 2- and 4-layer built-in stackups existed,
so `orangecrab` (6 layers) had no legal option. `default-<N>layer` now synthesises
a symmetric 1.6 mm FR4 stack for any N — still a user-selected approximation,
still stated in the report as `user:default-6layer`.

## Known gaps this corpus exposed

- ~~Inverter phase nodes are not found~~ — **fixed**: half-bridge midpoints are
  now recognised by topology (≥2 FET pads + a power-path element), so `vesc`
  reports its three phase nodes and their commutation loops.
- ~~Finding cap dominates dense boards~~ — **fixed**: round-robin per-rule
  selection before the cap.
- ~~`mppt-2420-lc` gets a switch node but no commutation loop~~ — **fixed
  2026-07-29**: the true `SW_NODE` was being rejected by the old *pad*-count
  rail filter (22 pads on 6 components — multi-pad power packages). The
  discriminators are now topological: components not pads, a bulk-capacitor
  crowd (>3 C components) marks a DC rail, and a bridge needs two distinct
  FET components. Corpus re-run bit-identical on every other board; lc now
  reports its 71 mm² commutation loop with C4 named at 4.4 mm. `/DCDC_OUT`
  (L + load switch + diodes) remains a known heuristic false positive.
- **`hackrf-one` still produces many individual hard-break rows.** These are
  genuine (no plane covers at all), so the *detour* aggregation does not apply,
  but a per-(layer, plane) roll-up for hard breaks would read better.
- ~~Missing: via stubs, λ/4 resonances, decoupling-cap ESL placement~~ —
  **added**. All three are excitation-free: they report the resonant frequency
  or the physical reach and leave relevance to the reader, since Faraday does
  not know the design's edge rates.
- **Polygon-aware coupling is still missing.** Zone-routed power paths are
  reported as a blind spot (`meta.polygonOnlyNets`), not analysed. This matters
  most on converter boards, where the high-current paths are pours.

## Reproducing

```sh
python3 scripts/fetch_corpus.py /tmp/faraday-corpus   # fetches from GitHub
python3 scripts/run_corpus.py  /tmp/faraday-corpus    # screens, writes JSON
```

Board licences vary (GPL-2.0, CERN-OHL-W-2.0, CC-BY-SA-4.0, 0BSD, and some
unstated); `manifest.json` records each. They are test inputs, not redistributed.
